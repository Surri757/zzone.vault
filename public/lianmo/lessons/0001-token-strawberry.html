DAY 01 · 第 1 题（基座模型方向）· 难度 ⭐

为什么全世界最聪明的模型，数不清 strawberry 里有几个 r？

附带考点：什么是 token？BPE 是怎么切词的？为什么中文更贵？
真题源：2024-08 全网热梗（网友实测 GPT-4o 数错 r）→ 演化为国内外大厂「tokenizer / 文本计数」类面试题 佐证：wdndev/llm_interview_note（15k★）Tokenizer 章 · OpenAI 官方 Tokenizer 文档 改写声明：以热梗为壳，考点保真（token / BPE / 字符盲区）

S1🎭 开场：先别查，盲猜一下

strawberry 这个单词里，有几个字母 r？

2024 年 8 月，无数网友在 X 上挑战各大模型这个问题，顶尖模型频繁答「2」——一夜之间成为全网热梗，随后变成面试官的最爱：「你说说，它为什么数不对？」

S2👀 一张图看懂：你看到的 vs 模型看到的

人类阅读时看到的是一个一个字母；而大模型从不直接读字母——它读的是 token（词元）。以 GPT 系常见分词为例，strawberry 会被切成 str / aw / berry 三块：

S3🧩 那么，token 到底是什么？

定义（面试必背）：token 是大模型读写文本的最小单位，介于「字符」和「单词」之间的子词片段。你输入的任何文字——英文、中文、代码、表情——都会先被 tokenizer（分词器）切成 token 序列，再转换成一串数字编号，模型从头到尾只跟这些编号打交道。

BPE 分词的直觉（不用记公式）：分词器训练时从单个字符起步，在海量语料里反复合并「最常一起出现的相邻片段」，直到词表达到上限（几万到十几万）。于是：

  • 高频词 → 一整块：如 the、我、hello
  • 低频词 → 拆成碎块：如 strawberry → str + aw + berry，甚至全新词 Agentverse → Agent + verse
  • 妙处：任何没见过的新词都能表示（大不了拆碎），词表又不会爆炸——这是「字符」和「整词」之间的黄金折中

📏 换算手感：英文 1 token ≈ 0.75 个单词 ≈ 4 个字符；中文 1 个汉字 ≈ 1~2 个 token（新词表已优化，老词表更贵）。

S4🔬 动手实验室：亲手切一切

S5💡 回到真题：完整的因果链

  1. 模型以 token 为最小单位读写文本 → 没有字符级视野
  2. berry 是一个不可拆的编号，里面的两个 r 对模型是「暗物质」
  3. 它回答「几个 r」靠的是训练语料里的统计印象，不是真去数 → 于是自信地答错
  4. 工程修复：别劝它「仔细数」，而是让它调用工具——写一行代码 s.count('r')，百分百正确

🚀 注意第 4 条：让模型「用工具补盲区」，正是今天第 2 题 AI Agent 存在的全部理由。这道题是完美的引子。

S6🔁 面试官追问链（点开前先自己答）

真实面试里，第一问只是入场券，连环追问才是得分差距。每层先看提示，再对照答案要点。

L1 · 「那你说说，为什么不直接用'字'或'词'？」
💡 提示：想想一个没见过的新词怎么办
词表能装下世界上所有的词吗？装不下的话，没见过的词怎么表示？

答案要点：① 按字符切：序列太长（同一句话长度翻 3~4 倍），训练与推理开销剧增，且单字符携带语义太稀薄；② 按整词切：词表爆炸（百万级），且新词、错拼、生僻词直接无法表示（OOV 问题）；③ 子词是折中：高频整体成块保效率，低频拆碎保覆盖，任何新词都有办法表示。这套算法叫 BPE（Byte-Pair Encoding，字节对编码）。

L2 · 「那中文用户用 GPT 为什么比英文用户贵？」
💡 提示：词表的「频率」是在谁的语料上统计的？
主流分词器的词表以英文语料为主统计频率，汉字在词表里覆盖得碎不碎？

答案要点：① 主流词表基于英文为主的语料训练，中文字/词覆盖零散，1 个汉字常要 1~2 个 token；② 同样一句话，中文 token 数更多 → API 按 token 计费更贵、上下文窗口占得更快；③ 延伸得分点：国产模型（Qwen、DeepSeek 等）针对中文优化了词表，中文效率显著更高——这也解释了为什么中文场景常选国产基座。

L3 · 「如果改成逐字符分词，会发生什么？」
💡 提示：序列长度 ×4，代价摊到哪里？
想想上下文窗口、推理成本、以及——字符任务会变好还是变坏？

答案要点：① 收益：数字母、拼写、字符级算术这类任务会变准（模型终于「看得见」每个字母）；② 代价：序列长度暴涨 → 注意力计算、上下文占用、推理成本全面上涨，长文本能力受损；③ 结论（面试官最想听的一句）：没有完美的分词，只有设计权衡——子词方案是「效率 × 覆盖」的工程最优解。顺带一提：这题答好，直接衔接 D9 的注意力复杂度话题。

S8🌌 发散思考（没有标准答案，值钱的是你的推理）

🌱 发散 1（换场景）：如果你是产品经理，怎么向老板解释「中文场景的 API 成本比英文高 40%」？

参考思路：用今天的机制链解释——词表以英文语料为主 → 汉字切得更碎 → 同等内容 token 数更多 → 计费与窗口占用双涨；再给方案：换中文优化词表的国产基座 / 压缩提示词 / 缓存固定 system prompt。能把机制翻译成成本与方案，就是面试里的「产品直觉」加分项。

🌱 发散 2（连类比）：token 之于模型，像什么之于人类——音节？偏旁？还是别的？

参考思路：都沾边但不全对。更像「阅读熟练单位」：母语者扫一眼「人工智能」是一个整块，看生僻字如「龘」就要拆成部件拼。模型词表 = 它的「识字量」，词表外的新词就像我们遇到生僻字——拆着猜。好的类比能让你永远记住这个概念，这就是「连类比」型发散的价值。

S11🎤 60 秒面试答案（把今天的理解压成一段话）

如果你在面试里被问到这道题，可以这样答：
「token 是模型读写文本的最小子词单位，由 BPE 分词器按语料频率切分——高频词整体成块、低频词拆碎，以此在效率和覆盖之间取折中。模型只有 token 级视野、没有字符级视野：strawberry 被切成 str、aw、berry，r 封在块内部，它只能靠训练语料的统计印象回答，所以会自信地数错。工程上的修复是让模型调用代码去数，而不是指望它自己看清楚。顺带一提，计费、上下文窗口、中英文成本差异，全都是按 token 计算的。」

📎 补课笔记 · Day 01 追问实录（2026-09-23）

🧩 BPE 合并小剧场（手推版）

微型语料（想象每句出现很多次）：① 我 爱 人 工 智 能 ② 人 工 智 能 够 用 ③ 我 爱 人 工

轮次 统计全部相邻对 → 选最高频 合并出新 token
0（初始）词表只有单字：我 爱 人 工 智 能 够 用—
1人+工 ×3 最高「人工」
2我爱 / 爱人工 / 工智 / 智能 并列 ×2（并列按实现规则选）「我爱」
3智+能 ×2「智能」
4人工+智能 ×2「人工智能」

结果：「我爱人工智能」从 6 个 token 压到 2 个（我爱 | 人工智能）。真实词表 = 把这个循环在海量语料上跑几万轮，直到词表封顶（如 10 万）。所以：高频组合成整块，低频组合留碎片——这就是全部机制。

🇨🇳 中文为什么碎：两个事实叠加

① BPE 只认频率：GPT 老词表的统计语料以英文为主，中文片段「排不上队」，很多没轮到合并；② 切不开就字节兜底：UTF-8 里 1 个汉字 = 3 个字节，没进词表的字退化成 2~3 个字节 token（实测里的 �）。这不是针对中文的设计，而是「频率统计 + 字节兜底」的副产物。国产模型（Qwen / DeepSeek）语料中文占比高，汉字大多 1 个 token——中文场景选国产基座更省，这是面试里可以主动说的工程判断。
