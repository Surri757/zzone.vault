DAY 01 · 第 2 题（AGENT 方向）· 难度 ⭐

什么是 AI Agent？它和 ChatGPT、普通 LLM 应用有什么区别？

附带考点：Agent 四模块 · ReAct 循环 · Workflow vs Agent · 停止条件与护栏
真题源：2025-26 各厂 Agent 岗通用开场首题（字节豆包 / 腾讯 / 阿里；海外 Agent 岗同源） 佐证：Lilian Weng《LLM Powered Autonomous Agents》· Anthropic《Building Effective Agents》· ReAct 论文 改写声明：概念框架题，考点保真（四模块 / 自主性 / ReAct）

S1🎭 开场：同一句话的两种命运

你对 ChatGPT 和对一个 Agent 说同一句话：「帮我订周五去上海的最便宜机票，别太晚到。」看看各自会发生什么——

💬 ChatGPT：一问一答

帮我订周五去上海的最便宜机票，别太晚到
好的，建议你打开购票 App，筛选周五航班按价格排序，注意取舍到达时间……（一段贴心的建议）
那 19:30 到的那种大概多少钱？
抱歉，我无法获取实时价格，建议以 App 显示为准～

📌 你推一步，它动一步。动手的永远是你。

🤖 Agent：自主循环

帮我订周五去上海的最便宜机票，别太晚到
收到目标 → 自己拆解：先查航班比价，再查周五上海天气，权衡后下单（下面的 S3 演示器可以亲手点一遍）
✅ 已订好周五 15:00 出发 ¥720 的航班；上海当晚有小雨，已提醒你留足接驳时间。

📌 给一个目标，它自己跑完全程。

⚖️ 公平起见：如今的 ChatGPT 网页版其实内置了联网、代码解释器等能力（它自己就在「Agent 化」）；我们这里对比的是裸 LLM API 和 Agent 系统的本质差异——下一步由谁决定。这个判据贯穿全题。

S3🎬 亲手点一遍：ReAct 循环步进演示

🧪 订票 Agent 的内部黑盒（点「下一步」逐帧播放）

Thought=思考 · Action=行动（调用工具） · Observation=观察（工具返回）。这个「思考-行动-观察」交替的范式叫 ReAct（Reason + Act，Yao et al. 2022，几乎所有 Agent 的心跳）。

S4🚗 面试标准答案骨架：Agent 四模块（整车比喻）

🧠 大脑（LLM）

理解目标、推理决策的发动机。第 1 题说过：它有 token 级盲区、会一本正经胡说——所以需要下面三个模块补短板。

🗺️ 规划（Planning）

把大目标拆成步骤、决定下一步做什么、边走边调整路线（上面演示器里的 Thought 就是它在工作）。

📼 记忆（Memory）

短期=本次对话的上下文（工作台）；长期=存进向量库的偏好与经验（油箱+行车记录仪）。D3 专题。

🔧 工具（Tools）

搜索、代码、API、数据库——模型的双手。Function Calling 是「伸手」的动作，MCP 是「标准插座」（D2 / D10 专题）。

S5📊 判别神器：自主性光谱

S6🔁 面试官追问链（点开前先自己答）

L1 · 「用你自己的话说，什么是 AI Agent？」
💡 提示：回想第 1 题「数 r」的修复方案
让模型调用工具去数——那如果不止数数，而是订票、写报告、做研究呢？把「调工具」变成一个循环会怎样？

答案要点：以 LLM 为大脑的自主系统——接收目标后，自己规划步骤、调用工具行动、观察结果、循环迭代直到完成。四模块：大脑 / 规划 / 记忆 / 工具。一句话判据：下一步做什么由模型决定。

L2 · 「为什么要循环？让模型一次生成完不好吗？」
💡 提示：十步任务，每步 95% 正确率，整体正确率是多少？
0.95 的 10 次方 ≈ 0.6——六成。复杂任务一步到位有多脆弱？

答案要点：一步全对的概率是各步正确率的连乘，任务越复杂衰减越快；拆步 + 每步观察反馈，模型可以中途发现并纠正错误（就像演示器里查完天气改订航班）。代价是更慢更贵——这正是 Agent 的 trade-off，也是「什么时候不该用 Agent」的答案种子。

L3 · 「如果 Agent 不设停止条件、不限工具权限，会发生什么？」
💡 提示：一个永不满足、又有你支付密码的循环
想想死循环烧 token、误删数据、错误下单——谁来踩刹车？

答案要点：① 无限循环烧钱（每圈都在耗 token）；② 高危动作不可逆（删库、转账、发邮件）。工程护栏：最大步数、预算上限、高危动作人工确认、沙箱隔离、权限最小化。这一问直接通向 D20 的 Agent 安全与评测——面试官在试探你的工程风险意识。

S7🕸️ 举一反三：这一题是整个 Agent 知识地图的目录

S8🌌 发散思考（没有标准答案，值钱的是你的推理）

🌱 发散 1（找反例）：找一个「不该用 Agent」的场景，并说明为什么

参考思路：高频率、强确定性的流程（退款审批流水线、每日报表生成）——路径固定就不需要模型自决，用 Workflow 更稳、更便宜、更好排查；Agent 的自主性在开放路径任务里才是资产，在固定路径里是风险。「该不该用 Agent」这个判断本身，就是 Anthropic 那篇文章的考点，也是产品经理和工程师天天吵的话题。

🌱 发散 2（换场景）：给「点外卖」设计一个 Agent——列出 3 个工具、2 类记忆、1 条护栏

参考设计：工具 = 查菜单/比价 API、下单 API、支付接口；记忆 = 长期（口味偏好、常点店铺）+ 短期（本次对话：今天几个人吃、预算）；护栏 = 支付前必须人工确认（对应 L3 的不可逆动作）。对照检查你自己的设计——少了记忆还是少了护栏？多数人第一版都漏护栏，这就是产品直觉的训练点。

S11🎤 60 秒面试答案（把今天的理解压成一段话）

如果你在面试里被问到这道题，可以这样答：
「Agent 是以 LLM 为大脑的自主系统：接收目标后自己规划步骤、调用工具、观察反馈、循环迭代直到完成，四个模块是大脑、规划、记忆、工具。它和 ChatGPT 的区别在自主性——chatbot 是人推一步动一步，Agent 是目标驱动自己跑完全程；和 Workflow 的区别在流程由谁决定——workflow 是人写死的代码路径，agent 是模型自决。典型范式是 ReAct：思考-行动-观察交替。工程上必须配最大步数、预算、高危动作人工确认这类护栏。」
🔗 今天两道题其实是一道题：第 1 题证明模型有「看不见块内字母」的盲区，修复方案是交给工具；第 2 题给「模型 + 工具 + 循环」起了名字——Agent。基模是发动机，烧的是 token；Agent 是整车，靠的是工具。接下来 27 天，我们两条线并行把它拆透。

📎 补课笔记 · Day 01 追问实录（2026-09-23）

追问：「为什么循环要比一步生成好？」「MCP 和 Function Calling 什么关系？」——一句话版：循环好，一半因为概率连乘塌方（观察纠错把单步正确率拉高），一半因为 Observation 带回新信息（实时票价这类事实，一步生成编不出来）；FC 与 MCP 不竞争——FC 是模型侧的「伸手能力」，MCP 是工具侧的「USB-C 插座标准」。

🔬 实测：一步生成 vs 循环+观察（解析式 + 10 万次蒙特卡洛模拟） 
假设：每步正确率 p=95%；出错时 90% 能被观察发现，重试一次
步数  |  一步生成 p^N  |  循环+观察 q^N
   1  |      95.0%     |      99.3%
   5  |      77.4%     |      96.4%
  10  |      59.9%     |      93.0%     ← 十步任务，成功率差 33 个百分点
  20  |      35.8%     |      86.5%     ← 任务越长，塌方越惨

蒙特卡洛模拟（10 步任务 × 100,000 次）：
  一步生成 成功率 ≈ 59.8%    循环+观察 成功率 ≈ 93.0%

读法：一步生成的成功率是各步正确率的连乘，步数一多就塌方；循环每步「走完睁眼看一眼」，把单步正确率从 95% 拉到 99.3%，连乘的底数变了，整条曲线就被抬起来了。代价：更慢更贵、可能死循环——所以需要最大步数/预算/高危确认这些护栏（呼应 L3 追问）。

💡 循环好的第二个原因：Observation 是「新信息」，不只是纠错

回看 S3 演示器第 6 步：模型查出「周五上海小雨」——这个事实它不可能一步生成出来（不在参数里），只能通过调工具拿回来。所以循环的本质是：每圈把一个「模型盲区」变成「已知事实」，再基于全部事实做下一步决策。这正是第 1 题「数 r 交给代码」的放大版：盲区交给工具，工具靠循环反复使用。

🔌 Function Calling vs MCP：不同层，是配合不是竞争
Function Calling MCP（Model Context Protocol）
是什么模型的能力：决定「伸手」并发出结构化调用（工具名+参数 JSON）开放的协议：工具统一接入标准——「AI 工具的 USB-C」
谁定的各家模型厂商，随 API 提供Anthropic 2024-11 开源，行业共建
解决什么模型怎么选工具、怎么传参数、程序怎么可靠接住工具怎么被发布/发现/复用：N 个应用 × M 个工具的 N×M 对接 → 写一次 MCP Server 处处可用（N+M）
没有它模型只能输出自然语言，代码无法可靠解析执行每个应用为每个工具手写胶水代码，工具成孤岛
一句话手的动作插座的标准

两者在同一趟调用里接力：MCP 把工具接入并列给模型看 → 模型用 FC 机制选择工具、发出参数 → MCP Server 执行 → 结果作为 Observation 回给模型。D10 会专门拆 MCP 的内部结构。
