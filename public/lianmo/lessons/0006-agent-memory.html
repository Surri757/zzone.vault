DAY 03 · 第 2 题（AGENT 方向）· 难度 ⭐+

Agent 的记忆怎么设计？短期 vs 长期分别是什么？为什么用向量库？记忆怎么写入和读出？

附带考点：两档架构 · 写读四步 · 向量 vs 关键词 · 记忆过时治理 ｜ 衔接 D2 窗口（短期记忆=窗口的正式化）与 D2 发散题「客服隔天失忆」
真题源：字节/阿里 Agent 岗高频原题方向（「设计一个有记忆的客服 Agent」「为什么记忆用向量库而不是普通数据库」） 佐证：Lilian Weng《LLM Powered Autonomous Agents》记忆一节 · Pinecone 向量数据库教程 · LangChain Memory 演进 改写声明：检索相似度为示意值，写读机制保真

S1🎭 开场：先盲猜一下

昨天聊得很投缘的客服 Agent，今天新开一个会话问它「我爱吃什么」，它答不上来。缺的最关键组件是？

提示：这是 D2 发散题的原班人马——今天给出正式答案。换多大的模型、调多高的 T，都改变不了"新会话里它什么都没看见"。

S2🧠 两档记忆：窗口是内存，向量库是硬盘

三个结论（面试直接背）：

  • 短期记忆 = 上下文窗口：装本会话的对话原文，容量有限、会话一开一关就清空——D2 的窗口放到 Agent 语境下的正式名字。
  • 长期记忆 = 向量库 + 结构化档案：跨会话持久。类比：窗口是内存，向量库是硬盘——关机（换会话）只清内存，不清硬盘。
  • 加分点：不是所有记忆都该向量化——偏好/关键事实适合提炼成结构化档案（键值、表格，可改可删），原文片段才进向量库。两句都说到，就是"设计过"的答案。

S3🔁 记忆怎么写入、怎么读出：两个四步

  • 写入 4 步：对话 → 提炼事实（"我叫小明、爱吃辣"）→ embedding（文字变向量）→ 入库（向量 + 原文 + 元数据）。
  • 读出 4 步：新问题 → embedding → 相似度 top-k 检索 → 注入 system/上下文，模型照常作答——对模型来说，记忆只是"提前塞进窗口的相关片段"。
  • 为什么是向量库：赢在语义——问「我爱吃什么」字面不含「辣」，也能命中「无辣不欢」，字面零重叠照样找得到；关键词（BM25）赢在精确词——订单号、型号、专有名词。生产答案：两者混合 + 重排（D15 专拆）。

S4🔬 动手实验室：记忆开关演示

🔀 同一个用户，两种 Agent

三回合固定剧本：回合 1、2 在昨天的会话 A，回合 3 是今天的新会话 B。先保持开关关闭重播一次看结局，再打开重播一次对比两栏。

长期记忆：关（不写入、不检索）

🔇 无长期记忆（只靠窗口）

回合 1 · 昨天 · 会话 A
我叫小明，无辣不欢！
你好小明！想聊点什么？
窗口：[…「我叫小明，无辣不欢」] ✓ 还在窗内
回合 2 · 昨天 · 会话 A（继续）
推荐个晚餐？
你无辣不欢，试试湘菜或川菜？
窗口：整段对话仍在 → 答得出（但这不是记忆，是窗口还没关）
回合 3 · 今天 · 新会话 B
我爱吃什么？
抱歉，这轮对话里没有相关信息，我答不上来……
窗口：新会话 = 空 ⌫ ｜ 向量库：从没写过 → 无处可查

🔊 有长期记忆（写入 + 读出）

回合 1 · 昨天 · 会话 A
我叫小明，无辣不欢！
记下了，小明！
✍️ 写入四步：提炼「叫小明」「爱吃辣」→ embedding → 入库 ↓
🗄️ 向量库（长期 · 跨会话）
#1 叫小明 · vec[0.12,-0.40,…]#2 爱吃辣 · vec[0.88,0.07,…]
回合 2 · 昨天 · 会话 A（继续）
推荐个晚餐？
你无辣不欢，试试湘菜或川菜？
和左栏一样靠窗口即可——长期记忆是补充，不是替代
回合 3 · 今天 · 新会话 B
我爱吃什么？
🔎 读出四步：query → embedding → top-k：#2 爱吃辣（余弦 0.91）✓　#1 叫小明（0.44）→ 注入 system
问题字面没有「辣」→ 语义命中，这就是向量的价值
你无辣不欢啊！今天想吃湘菜还是川菜？
组件行为定义：① 开关只控制一件事——回合 1 结束时是否执行「提炼 → embedding → 入库」；② 回合 2 在同一会话（窗口还在）→ 两栏都答得出；回合 3 新会话（窗口清空）→ 两栏分化；③ 重播按时间顺序放三回合，右栏的入库/检索徽章随剧情出现，非当前模式的栏位变灰。
观察任务：回合 3 有记忆栏命中的是哪条记忆、相似度多少？为什么问题里没有「辣」字也能命中？

S5🔁 面试官追问链（点开前先自己答）

L1 · 「短期记忆能不能靠无限加长窗口解决？」
💡 提示：窗口加到 2M，昨晚的会话还在里面吗？
窗口装的是"这一场对话"；昨晚那场是另一场对话。

答案要点：不能。① 成本/延迟随长度上涨、注意力稀释仍在（D2 的 U 形曲线）；② 更根本的：窗口解决的是"容量"，长期记忆解决的是"持久"——会话一关窗口照样清空，再长也留不住昨天。"装得下 ≠ 记得住"，这句就是 L1 的满分句。

L2 · 「为什么非要向量库，关键词搜索不行吗？」（字节/阿里爱问）
💡 提示：「爱吃辣」和「无辣不欢」有几个字相同？订单号呢？
一个靠意思接近，一个靠字面精确——各吃各的赛道。

答案要点：各有赛道。① 向量赢在语义：embedding 把意思编码进几何空间，"爱吃辣"≈"无辣不欢"，字面零重叠也命中；② 关键词（BM25）赢在精确：订单号、型号、专有名词，倒排索引零成本、可解释、不跑偏；③ 生产答案：混合检索（两路召回）+ rerank 重排（D2 补课讲过的漏斗，D15 拼成完整链路）。只夸向量或只贬关键词，都算答半题。

L3 · 「记忆错了 / 过时了怎么办？」（区分度题）
💡 提示：用户昨天说爱吃辣，今天说最近胃不舒服不吃辣了——库里那条旧记忆怎么办？
回忆一下手机通讯录：新号码是"覆盖"还是"并存"？

答案要点：记忆不是只增不改的账本。① 写入端：重要度过滤 + 去重，别把闲聊全囤进去；② 冲突消解：记忆带时间戳和来源，读出时新事实覆盖旧事实（recency 优先），用户明说的优先于模型推测的；③ 遗忘机制：TTL 过期、显式删除权（合规要求）；④ 读出端：检索结果只是"参考资料"，让模型引用记忆作答而不是盲信。能主动说出"记忆需要生命周期管理"，就是区分度所在（D17 记忆系统设计专拆）。

S8📇 今日知识卡（点击翻面，复盘日要刷）

「短期记忆 = 窗口（内存，会话级易失）；
长期记忆 = 向量库 + 档案（硬盘，跨会话）。
写入：提炼→向量→入库；
读出：向量→top-k→注入。」
📇 点击卡片翻面 → 考点 / 易错 / 出处
考点：两档架构 · 写读各四步 · 向量（语义）vs BM25（精确词）混合 · 记忆治理（时间戳/覆盖/遗忘）
易错：以为窗口能跨会话；以为所有记忆都该向量化；记忆只增不改；把长期记忆当成窗口的替代（是补充）
出处：Lilian Weng《Agent》记忆一节 · Pinecone 教程 · 字节/阿里「设计有记忆的客服 Agent」原题方向

S9🎤 60 秒面试答案（把今天的理解压成一段话）

如果你在面试里被问到这道题，可以这样答：
「Agent 记忆分两档：短期就是上下文窗口，装本会话原文，容量有限、关掉即清空；长期是外挂的向量库加结构化档案，跨会话持久——窗口是内存，向量库是硬盘。写入四步：从对话提炼事实、embedding 向量化、连同原文和元数据入库；读出四步：新问题向量化、相似度取 top-k、把片段注入上下文、模型照常生成。用向量库是因为语义检索：问『我爱吃什么』能命中『无辣不欢』，字面不重叠也能找到；但订单号、型号这类精确词关键词更强，生产上常用混合检索加重排。最后记忆还要治理：带时间戳、新事实覆盖旧事实、支持遗忘和删除——它不是只增不改的账本。」
